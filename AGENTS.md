# AGENTS.md — PoKingHill (UNITY_AGENT)

Standing directives for any coding agent working in this repo. Project-specific anchors are in *italics*.

## 1. Project Setup & Git Workflow

- **Project context & versioning:** Read the `/DOCS` summaries before starting.
  *Here: `docs/` (screenshots), plus `tasks.md` (build checklist and contract) and `rl_optimization_log.md` (run log and decisions).*
  Display the deployment build version `YYMMDD` in the bottom-right corner, generated by an automated build script from the current date or the Git commit date.
- **Branching & sync:** Work only on `master`. Commit pending changes before any git sync (pull, rebase, push).
- **Scene construction & assets:** Create prefabs and objects through the Unity CLI (or Unity MCP).
  When modifying Blender scenes via Blender MCP, archive the original `.blend` in `Assets/Art/Raw/` and export a GLB copy to `Assets/Art/Exports/GLB/` for reference.
  *Existing generated art lives in `art/` (e.g. `art/kim/Kim.glb`, built by `tools/make_kim.py`).*
- **Performance safeguards:** Disable editor throttling, enable **Run In Background**, and keep the editor auto-ticking via MCP/CLI.
- **UI documentation:** Save every UI change as an HTML report with annotated before/after screenshots in `SCREENSHOTS/`.
  *Existing captures are in `docs/screenshots/`.*

## 2. Training Environment & Execution

- **Engine routing:** Train in MuJoCo/Newton (Android builds via [mujoco-bin](https://github.com/joanllobera/mujoco-bin/)). *Override: skip this when using `mlagents`.*
  *Here: MuJoCo Warp standalone training under `training/` (uv project); Unity runs MuJoCo via `org.mujoco`, with PhysX bypassed.*
- **Mesh & rig pipeline:** Validate skinned meshes and extract rig hierarchies before MuJoCo/Newton training.
- **Inference runtime:** Export trained policies to ONNX and run them in Unity with Sentis.
  *Here: `com.unity.ai.inference` 2.6.1 (Sentis' successor); models in `Assets/PoKingHill/Models/`, export via `training/scripts/export_policy.py`; reports via `training/scripts/make_report.py`.*
- **Resource management & housekeeping:**
  - Keep simulation UIs visible.
  - Close Unity during pure RL runs, or sessions over 30 min, when that speeds up training.
  - Automatically prune abandoned run directories, dummy checkpoints, and TensorBoard logs under 5,000 steps.
- **TensorBoard & graduation metrics:**
  - Start TensorBoard when training launches.
  - Export a policy only after it passes graduation: mean reward ≥ target across 100 consecutive episodes, with zero NaN gradients.
  - For runs over 30 min, write an HTML report with the top-3 metric screenshots, delta comparisons against the previous run, and a 3-tier summary (Toddler, Child, Adult).
- **Telemetry:** Stream agent actions, win/loss stats, and kinematics to local storage or Azure Tables, for later analysis and debugging.

## 3. Physics, Biomechanics & Self-Collision

- **Physical realism:** Use real-world gravity, proportional mass, and realistic joint forces.
- **Primitive colliders:** Enclose skinned meshes with primitive colliders (capsules, boxes, spheres). Never use raw bones or visual meshes as colliders.
- **Self-collision matrix:** Verify zero overlap in T-pose, rest pose, and swing arcs. Enable collision for every pair of segments except direct parent-child joints.

## 4. Response Formatting

- **TL;DR rule:** Append a 20-word TL;DR to any response longer than 100 words.
