# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## What this is

PoKingHill: king-of-the-hill between physics-simulated human bodies: Kim, a scanned 56 kg woman, Trump, a 102 kg man from a rigged GLB, and Grandpa, an 86 kg man rigged from an unrigged GLB (more custom rigged meshes to come). The Unitree G1 robot, the first body, left the game on 2026-10-20; its training code, checkpoints, ONNX brains and gates stay, the human recipes were built from it, and what it taught is in `training/TRAINING_LESSONS.md`. Brains are trained in Python on MuJoCo Warp and run in Unity 6000.6.0f1 through the `org.mujoco` plugin and `com.unity.ai.inference` (Sentis' successor). **PhysX is never used**: Unity's physics mode is Script, every scene must have zero Collider/Rigidbody, and MuJoCo is the only simulator in both worlds.

`DOCS/tasks.md` is the build contract (phases 0, A-D, rung bars R0-R5). `DOCS/rl_optimization_log.md` is the chronological record of every run, measurement and decision, newest at the bottom. Read the bottom of it before changing training or parity tooling.

## Commands

Python (from `training/`, uv project, Python 3.11, CUDA torch). The `.sh` scripts call `.venv/Scripts/python.exe` directly.

```bash
uv run python scripts/train.py --rung r0 --num-envs 4096 --iters 1500 [--resume ckpt.pt | --warm ckpt.pt] [--opponent a.pt b.pt:stand] [--reward self_edge=-5]
uv run python scripts/eval.py --rung r4league --ckpt runs/league/careful1.pt --opponent runs/league/gen3.pt --seeds 3 --num-envs 256
bash scripts/judge.sh <league checkpoint name>       # champion bars: vs standing walker, gens 3-7, champion, itself
uv run python scripts/export_policy.py --ckpt <ckpt.pt> --name attacker   # -> Assets/PoKingHill/Models/<name>_policy.onnx
uv run python scripts/duel_stats.py --policy attacker --rounds 200 [--getup [--hill-rule]]   # CPU MuJoCo reference for the Unity statistics gate (--getup --hill-rule: the game's rule)
uv run python scripts/getup_stats.py --policy getup --drops 200          # CPU reference for the get-up gate (RunGetupStats)
uv run python scripts/collision_audit.py             # self-collision of G1/Kim/Trump/Grandpa (--robots) in zero, rest, T-pose and swing arcs -> SCREENSHOTS/collision-<YYMMDD>/report.html
bash scripts/audit_all.sh                            # drive_audit.py of every shipped brain: action clamp / torque-limit shares, raw-output p95 -> runs/audits/
uv run python scripts/action_scale.py runs/audits/drive_careful1.json --out runs/audits/scale_careful1.json   # per-joint action scale for --action-scale
uv run python scripts/step_response.py               # per-joint step response, damping ratio, left/right hold symmetry of every body
bash scripts/reward_audit_all.sh                     # reward_audit.py: term shares, zero-clip binding, stall / farm / dominance flags
uv run python scripts/obs_audit.py --ckpt <ckpt> --unity assets/<body>/unity_obs_<tag>.jsonl [--brain <onnx name>]   # Unity inputs vs training (RunObsDump)
uv run python -m koth.build_mjcf [4p|5p|6p|7p]       # regenerate MJCF scenes, model_dump_*.json and joint_map.json
uv run python -m koth.build_mjcf game                # the game's bodies koth_game (humans only), then ParityBatch.ImportOne -kothScene koth_game + GameScene.RefreshBodies
uv run python -m koth.env                            # env smoke test
uv run python scripts/prune_runs.py [--apply]        # intermediate checkpoints, short / abandoned runs, stale logs under runs/ (dry run by default)
```
Repo housekeeping: `bash tools/cleanup_unused.sh [--apply] [--old-gates] [--builds]` (dry run by default) deletes what earlier cleanups set aside in `archive/`, unused MuJoCo import folders (found by GUID, never listed by hand) and runs `prune_runs.py`. One-off training queues live in `training/scripts/archive/`.

`KOTH_ROBOT=kim`, `trump` or `grandpa` switches every Python entry point (and `export_policy.py`'s output folder to `Models/<robot>/`) to that human's body; G1 is the default. Human rungs are `<robot>_r0b` / `<robot>_r1b` (walking recipe, `env.human_overrides`), `trump_r4bull` (Trump's fight) and `<robot>_hill` (the game's one brain per body: 112 inputs, the nearest opponent only, trained against the other two humans' frozen fighters, one per slot: `--opponent a.pt:slot1 b.pt:slot2`, half the worlds duels with the third body benched: `env duel_share`; queue `scripts/queue_hill.py`, which replaces `Models/<robot>/fighter_policy.onnx` only when it wins more three-ways and keeps its duels); Grandpa's queue is `scripts/grandpa_queue.sh` (walker, then Kim's `r4att` + `r4league` fighter recipe). Run one 4096-env training at a time: two plus an eval fill the 12 GB GPU and slow everything ~100x. TensorBoard logs and checkpoints go to `training/runs/` (git-ignored; `runs/league/champion.txt` names the current champion).

## Architecture

**One model, two simulators.** `koth/build_mjcf.py` is the single source of the physics model: it writes the training MJCF, a `_unity.xml` variant stripped of what the plugin cannot import, `model_dump_<tag>.json` (the parity reference) and `joint_map.json` (canonical 29-joint order). The MuJoCo part of every Unity scene is *imported* from that XML by `ParityBatch`, never hand-built; the game scene around it is composed by hand (see Scenes). Change physics on the Python side and re-import; never edit imported MuJoCo components in Unity. Settings the plugin cannot import (`ls_iterations`, keyframes, contact pairs) are either avoided in the MJCF or written from C# after init.

**Control loop, mirrored on both sides.** 2 ms physics step, policy every 10th step (50 Hz). Observations: 103 locomotion inputs (`koth/obs.py:build_obs` = `ObsBuilder.cs`), plus 9 combat inputs for 112-dim brains (`build_combat` = `ObsBuilder.FillCombat`). The 3 command slots come from a geometric goal law (`obs.goal_command` = `GoalCommand.cs`), not from extra observations; training's `obs.tactic_goal` moves its goal point in the `r4tactic` rung (Unity's Tactician was cut on 2026-10-21). `ctrl = default + 0.5·action`, unless the brain carries `<name>_action.json` (tanh map, per-joint scale, torque window: `koth/action_map.py` = `ActionMap.cs`, read by `PolicyRunner` and `duel_stats.py`). Any change to one side of these pairs must be made on the other, then re-gated.

**Unity runtime** ([Assets/PoKingHill/Scripts](Assets/PoKingHill/Scripts), one folder per concern: `Brain/` the control loop mirrored in Python (obs, goal law, action map, `PolicyRunner`), `Match/` rules and state (director, events, settings, sea, sensors, telemetry), `Presentation/` cameras, effects, audio, looks, `Hud/` the UI (`HudView` split into partial files), `Diagnostics/` parity probes and the command line): everything hooks `MjScene` events (`postInitEvent`, `preUpdateEvent`, `postUpdateEvent`) and reads/writes `mjData` through unsafe pointers. No Instantiate/Destroy, no scene reloads: rounds reset by writing qpos/qvel. `PolicyRunner` must rewrite held ctrl in `preUpdateEvent` every step because `MjActuator.OnSyncState` zeroes ctrl after each `mj_step`. The physics tick is allocation-free; keep it that way.
- `MatchDirector`: the match state machine (`Menu → Fight → Result (→ Replay) → Fight | Menu`); quick match (everyone with a brain at once), custom, tournament; every agent is a brain (no human player). Seats agents (`roster`, class `Agent`: a brain and how it is driven) on bodies of their own kind (`bodies`, the `PolicyRunner`s: `g1`/`kim`/`trump`/`grandpa`), reorders `bodies[]` at every launch (cache your own copy if you index by body), parks unused bodies 50 m up, points each brain at one opponent (nearest, or with `Targeting.Opportunist` the one easiest to push off; brains were trained 1v1). The statistics gate (`statsRounds`) bypasses Result and the presentation.
- Presentation never gets called by the director: it subscribes to `MatchEvents` (state, round start/end, knock-out and its credit, down/recovered, impact, footfall, splash, caption). `HudView` (UI Toolkit, styles in `UI/Hud.uss` with a six-step type scale, one 9:16 column, no scrolling; one row of avatar badges with a `VitalsBar`, knock-out feed, intro card, replay bar with a draggable playhead, tabs Play/Agents/Settings on a bottom sheet that swipes down to a peek pill and turns dense when it would not fit; every option sits on the Settings page in sections Match/Picture/Sound/Advanced; Picture is Quality plus one Cinematic switch (effects, camera cuts and shake, slow motion); Advanced → Developer tools shows the FPS pill (dodges `Screen.cutouts`) and the debug button, debug tabs Perf/View/Tools, where View holds the overlays, win odds and captions), `BroadcastCamera` (Cinemachine, the only camera; intro crane on a Splines path + per-fighter orbit), `ReplaySystem` (disables `MjScene`, replays qpos via `mj_kinematics`, restores the exact state), `MatchFx` (particles, decals, post punch, shockwave via the `ShockwaveFeature` renderer feature, lightning, danger light), `BodyLook` (team paint, overlays, and the `FX/Fighter.shader` surface: seat-colour rim that turns red at the edge, wear from contacts, wet after the sea, hit flash), `TimeWarp` (slow motion at the rim and hit stop: `Time.timeScale` only, never in gates or replays), `QualityTier` (Low/Medium/High/Auto presets on the camera and sun, frame-time telemetry), `WinOdds`, `Commentator` (offline caption templates), `MatchLog` (local telemetry JSONL + Elo `Ladder` with record, KOs, assists in `persistentDataPath`). Options live in `GameSettings` (PlayerPrefs); the defaults are the least cluttered game (no intro, auto replay or developer tools, so no captions or win odds either). There are no network features: Twitch votes, live weather, cloud voice, Claude commentary and Azure upload were cut on 2026-10-20; Stamina + hype, Hazards, the Tactician (with `MlpNet`, `Tactics` and `export_mlp.py`), the Classic camera and the Dogpile/Grudge/Vulture targeting on 2026-10-21 (sources in `archive/clean-261021/` until `tools/cleanup_unused.sh --apply`).
- Match state `Intro` (tale of the tape) sits between Menu and Fight on a match's first round: bodies stand passively (no brain), then `ArmBrains` + `NewRound` place them afresh. Gates and auto runs skip it; tests call `SkipIntro()`.
- Sensors and mechanics, all inert in the statistics gates unless a gate asks: `ContactLedger` (pairwise pushing impulse from `mj_contactForce`, knock-out credit and assists), `Biometrics` (capture point vs the planted feet = balance, capture point vs the rim = edge, strain history). The get-up rule is always on in the game (the hill rule: every fall on the mountain top gets up with the body's get-up brain, no count, no limit; only leaving the top is a knock-out; the sea still ends a round) and lives in `MatchDirector.OutWithGetUp` (body-kind brains in `getupBrains`, `PolicyRunner.SetGetUp`), mirrored by `duel_stats.py --getup`.
- `Sea` (rising water = round clock, buoyancy via `xfrc_applied` for every fighter body), `ImpactSynth` (procedural audio, no audio files: hits by material and body through `SoundPool`'s 3D one-shots whose clips are synthesized at start, sliding and grinding from the contact list, ambience beds of wind, surf and crowd in `OnAudioFilterRead`; mix channels in `GameSettings`), `SkinFollower` (a human's mesh follows its MuJoCo bodies), `ProjectilePool` (re-pins the MJCF's parked boxes; the hold-parity gate fires them).
- Parity/diagnostic components (`ParityProbe`, `PolicyParityProbe`, `ModelDumpCheck`, `PerfProbe`, `AutoShot`) are inert unless their `-koth*` switch is given; switches are read through `Cli` (the editor's own command line: a CLI `eval` cannot set them, so gates that need parameters have overloads). `GetupProbe` is added only by `RunGetupStats`.

**Scenes.** `Testbed_<tag>.unity` per imported model (`flat_1p`, `koth_1p/2p/4p/7p`, `koth_game`, `kim_*`, `trump_*`, `grandpa_*`); the robots come from the `robots` list in `model_dump_<tag>.json`. The game is `Scenes/Game.unity`, composed and saved in the editor: tune lights, fog, camera, map, sea and the match logic on `KothRig` by hand, and the HUD, cameras, effects and sound pool in `Prefabs/Presentation.prefab` (an instance in the scene). Nothing rebuilds it: `GameScene.RefreshBrains` rewrites only the roster (the human brains; G1 agents only in gate scenes with G1 bodies), `GameScene.RefreshBodies` only the MuJoCo tree, runners and skins from `Testbed_koth_game` (two bodies of every human kind: `python -m koth.build_mjcf game [bodies...]`, list `GAME_BODIES`; add a new body there). Shared assets live in `UI/` and `FX/` (every imported arena uses `FX/Arena.mat`). The gates compose `Gate_duel_2p.unity`, `Gate_duel_<robot>_2p.unity` and `Gate_ffa_4p/7p.unity` (git-ignored) as copies of the game scene with the bodies of `koth_2p`, `koth_4p` or `koth_7p` (`GameScene.Compose`). The HUD's version is YYMMDD of the last commit (`Editor/BuildVersion.cs` → `Resources/build_version.txt`, git-ignored).

**Gates.** Training checkpoints are only trusted after the Unity gate: trajectory parity for single-agent rungs (replay error < 1e-4, closed-loop pelvis < 10 cm), statistical parity for combat (decided share and winning-time quartiles vs `duel_stats.py`), because adversarial rounds diverge chaotically after contact. Known rules mismatch: training/`eval.py` end a round on own foot-shin contact, Unity and `duel_stats.py` do not (`eval.py --leg-contact-rule unity` measures the Unity rule; staged rungs turn it off). Staged next steps and their Unity mirrors: `training/STAGED_TRAINING.md`.

**Art.** Blender scripts generate render-only assets: `tools/make_mountain_map.py` → `Assets/PoKingHill/Maps/Mountain` (Poly Haven CC0, git-ignored sources in `tools/polyhaven`; hill in three LODs, rocks, crags, ruins, banners swaying in `FX/Banner.shader` from MatchFx's `_KothWind`, Cycles-baked AO; headless `blender -b --factory-startup --python tools/make_mountain_map.py`, the Store build via `%LOCALAPPDATA%/Microsoft/WindowsApps/blender-launcher.exe`, which does not pass stdout back; archives `Assets/Art/Raw/Mountain~/Mountain.blend` and `Assets/Art/Exports/GLB/Mountain.glb`), `tools/make_kim.py` (reads `Assets/Art/Raw/Kim/Kim.glb`) → `Assets/PoKingHill/Fighters/Kim` + `training/assets/kim/kim_rig.json`, then `koth/build_kim.py` (her profile) and `koth/build_human.py` (the builder shared by every human) build her MJCF with the G1's joint names and order so networks and runners are shared. A rigged GLB needs no Blender: `tools/make_glb_fighter.py <robot>` reads `Assets/Art/Raw/<Name>/<Name>.glb`, writes `<robot>_rig.json` and a 2k-texture copy in `Fighters/<Name>/` (imported by glTFast), and `koth/build_<robot>.py` holds the body's mass, strength and gains (Trump: `koth/build_trump.py`). An unrigged mesh goes through headless Blender: `tools/make_grandpa.py` cleans `Assets/Art/Raw/Grandpa/Grandpa.glb`, places joints from adult proportions and the mesh, skins with bone heat, exports a T-pose FBX with a walk cycle (`Assets/Art/Exports/FBX/Grandpa/Character_TPose.fbx`) and the game asset `Fighters/Grandpa/grandpa.fbx` with the arms hanging (profile `koth/build_grandpa.py`).

**Line endings.** The index mixes CRLF and LF files (`core.autocrlf=true`). `sed -i` and some tools rewrite CRLF files as LF, which turns a small edit into a whole-file diff; check `git ls-files --eol -m` and restore CRLF (`sed -i 's/\r*$/\r/'`) before committing.
