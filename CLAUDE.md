@AGENTS.md

## What this is

PoKingHill: king-of-the-hill between physics-simulated humanoids (Unitree G1, plus Kim, a scanned 56 kg human body). Brains are trained in Python on MuJoCo Warp and run in Unity 6000.6.0f1 through the `org.mujoco` plugin and `com.unity.ai.inference` (Sentis' successor). **PhysX is never used**: Unity's physics mode is Script, every scene must have zero Collider/Rigidbody, and MuJoCo is the only simulator in both worlds.

`tasks.md` is the build contract (phases 0, A-D, rung bars R0-R5). `rl_optimization_log.md` is the chronological record of every run, measurement and decision, newest at the bottom. Read the bottom of it before changing training or parity tooling.

## Commands

Python (from `training/`, uv project, Python 3.11, CUDA torch). The `.sh` scripts call `.venv/Scripts/python.exe` directly.

```bash
uv run python scripts/train.py --rung r0 --num-envs 4096 --iters 1500 [--resume ckpt.pt | --warm ckpt.pt] [--opponent a.pt b.pt:stand] [--reward self_edge=-5]
uv run python scripts/eval.py --rung r4league --ckpt runs/league/careful1.pt --opponent runs/league/gen3.pt --seeds 3 --num-envs 256
bash scripts/judge.sh <league checkpoint name>       # champion bars: vs standing walker, gens 3-7, champion, itself
uv run python scripts/export_policy.py --ckpt <ckpt.pt> --name attacker   # -> Assets/PoKingHill/Models/<name>_policy.onnx
uv run python scripts/duel_stats.py --policy attacker --rounds 200        # CPU MuJoCo reference for the Unity statistics gate
uv run python -m koth.build_mjcf [4p|5p]             # regenerate MJCF scenes, model_dump_*.json and joint_map.json
uv run python -m koth.env                            # env smoke test
```

`KOTH_ROBOT=kim` switches every Python entry point (and `export_policy.py`'s output folder to `Models/kim/`) to Kim's body; G1 is the default. Run one 4096-env training at a time: two plus an eval fill the 12 GB GPU and slow everything ~100x. TensorBoard logs and checkpoints go to `training/runs/` (git-ignored; `runs/league/champion.txt` names the current champion).

`ParityBatch` methods ([Assets/PoKingHill/Editor/ParityBatch.cs](Assets/PoKingHill/Editor/ParityBatch.cs)):
- `ImportAll` / `ImportOne -kothScene koth_5p`: import `training/assets/<robot>/scene_<tag>_unity.xml` into `Testbed_<tag>.unity` (`-kothRobot kim` for Kim).

## Architecture

**One model, two simulators.** `koth/build_mjcf.py` is the single source of the physics model: it writes the training MJCF, a `_unity.xml` variant stripped of what the plugin cannot import, `model_dump_<tag>.json` (the parity reference) and `joint_map.json` (canonical 29-joint order). Unity scenes are *imported* from that XML by `ParityBatch`, never hand-built, and `Demo_duel.unity` is regenerated by `BuildDuelDemo`. Change physics on the Python side and re-import; never edit imported MuJoCo components in Unity. Settings the plugin cannot import (`ls_iterations`, keyframes, contact pairs) are either avoided in the MJCF or written from C# after init.

**Control loop, mirrored on both sides.** 2 ms physics step, policy every 10th step (50 Hz). Observations: 103 locomotion inputs (`koth/obs.py:build_obs` = `ObsBuilder.cs`), plus 9 combat inputs for 112-dim brains (`build_combat` = `ObsBuilder.FillCombat`). The 3 command slots come from a geometric goal law (`obs.goal_command` = `GoalCommand.cs`), not from extra observations. `ctrl = default + 0.5·action`. Any change to one side of these pairs must be made on the other, then re-gated.

**Unity runtime** ([Assets/PoKingHill/Scripts](Assets/PoKingHill/Scripts)): everything hooks `MjScene` events (`postInitEvent`, `preUpdateEvent`, `postUpdateEvent`) and reads/writes `mjData` through unsafe pointers. No Instantiate/Destroy, no scene reloads: rounds reset by writing qpos/qvel. `PolicyRunner` must rewrite held ctrl in `preUpdateEvent` every step because `MjActuator.OnSyncState` zeroes ctrl after each `mj_step`. The physics tick is allocation-free; keep it that way.
- `DemoDirector`: menu → round → winner panel → menu, IMGUI HUD. Seats ticked roster agents on bodies of their own kind (`g1`/`kim`), parks unused bodies 50 m up, retargets each brain to the nearest fighter still in (brains were trained 1v1).
- `Sea` (rising water = round clock, buoyancy via `xfrc_applied`), `MatchCamera`, `ImpactSynth` (procedural audio from contacts in `OnAudioFilterRead`, no clips), `SkinFollower` (Kim's scanned mesh follows MuJoCo bodies), `ProjectilePool`.
- Parity/diagnostic components (`ParityProbe`, `PolicyParityProbe`, `ModelDumpCheck`, `PerfProbe`, `AutoShot`) are inert unless their `-koth*` switch is given.

**Scenes.** `Testbed_<tag>.unity` per imported model (`flat_1p`, `koth_1p/2p/4p/5p`, `kim_*`). The game uses `koth_5p` (four G1 + Kim as `e_`); the two-fighter gates rebuild `Demo_duel.unity` from `koth_2p`. Both write the same file, so whichever ran last is on disk.

**Gates.** Training checkpoints are only trusted after the Unity gate: trajectory parity for single-agent rungs (replay error < 1e-4, closed-loop pelvis < 10 cm), statistical parity for combat (decided share and winning-time quartiles vs `duel_stats.py`), because adversarial rounds diverge chaotically after contact. Known rules mismatch: training/`eval.py` end a round on own foot-shin contact, Unity and `duel_stats.py` do not.

**Art.** Blender scripts generate render-only assets: `tools/make_mountain_map.py` → `Assets/PoKingHill/Maps/Mountain` (Poly Haven CC0, git-ignored sources in `tools/polyhaven`), `tools/make_kim.py` → `Assets/PoKingHill/Fighters/Kim` + `training/assets/kim/kim_rig.json`, then `koth/build_kim.py` builds her MJCF with the G1's joint names and order so networks and runners are shared.
